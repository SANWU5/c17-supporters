# C17 鸣谢墙

这个仓库保存 C17 鸣谢墙的公开名单与头像。名单可以独立于 APK 更新，供应用读取。

> 感谢每一位为项目提供捐赠、反馈和帮助的伙伴。你们的支持，让项目得以持续改进，也让每一次更新更有动力。

当前 `thanks.json` 是空名单，尚未导入任何真实用户。`examples/thanks.example.json` 只有虚构示例，不能作为正式名单展示。

## 分类

| 展示分类 | 对应字段 | 用途 |
| --- | --- | --- |
| 特别鸣谢 | `featured: true` | 单独突出展示需要特别感谢的伙伴，与支持金额无关。 |
| 捐赠支持 | `group: "donation"` | 提供捐赠支持的伙伴。 |
| 其他支持 | `group: "support"` | 提供测试、反馈、开发、设计等帮助的伙伴。 |

“特别鸣谢”是独立标记，不是第三个所属分组。同一个人只保存一条记录；同时提供捐赠和其他帮助时，可归入捐赠支持，并在说明里写明其他贡献。展示端可以把特别鸣谢条目放入独立区域，并从普通列表中排除，避免重复展示。

## 用户字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| `id` | 必填 | 唯一、稳定的标识，例如 `p001`；改昵称时保留原 ID。 |
| `display_name` | 必填 | 对方希望公开展示的昵称，可包含 `@`。 |
| `group` | 必填 | `donation` 或 `support`。 |
| `avatar` | 可选 | 头像路径，例如 `avatars/p001.webp`；缺省或 `null` 时显示默认头像。 |
| `featured` | 可选 | 是否特别鸣谢，默认 `false`。 |
| `note` | 可选 | 简短的鸣谢或贡献说明，默认留空。 |
| `order` | 可选 | 展示顺序，数字越小越靠前，默认 `100`；相同时按原列表顺序。 |
| `visible` | 可选 | 是否展示，默认 `true`。 |

仓库面向公开展示，只保存本人认可公开的昵称、头像和说明。不要保存付款记录、金额、订单号、联系方式或其他私人信息。`visible: false` 只控制页面显示，不能让公开仓库里的数据变成私密。

## 添加或更新名单

1. 编辑根目录 `thanks.json`，在 `people` 中添加或修改用户记录。可以参考示例文件，不要复制示例用户进正式名单。
2. 如需头像，将图片上传到 `avatars/`，建议用稳定 ID 命名，例如 `p001.webp`。
3. 每次发布名单修改时，将 `revision` 加 1，并更新 `updated_at` 日期。
4. 检查每个 ID 都唯一、头像路径对应实际文件，再提交修改。

新增一人的最简记录：

```json
{
  "id": "p001",
  "display_name": "请填写公开昵称",
  "group": "donation"
}
```

需要特别鸣谢时，在该用户原有记录中加入 `"featured": true`，不要新建第二条记录。仅修改显示名称、说明或头像时，保持 `id` 不变。

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `thanks.json` | 应用读取的正式名单。 |
| `schema.json` | 用于校验字段、分类和格式的 JSON Schema。 |
| `examples/thanks.example.json` | 不含真实用户的格式示例。 |
| `avatars/` | 经允许公开展示的头像。 |

`schema_version` 表示数据结构版本，普通名单修改无需更改。`revision` 表示内容版本，每次更新递增。`updated_at` 使用 `YYYY-MM-DD` 格式。`groups` 数组的顺序决定普通分类的展示顺序。

Schema 不能检查用户 ID 是否重复、头像文件是否存在，也不能判断内容是否真实；这些仍需维护者核对。

## 应用接入建议

应用仅从根目录 `thanks.json` 读取名单，头像路径相对于仓库内容地址解析。首次使用显示 APK 内置名单，之后优先显示上次有效缓存；用户打开鸣谢墙时，若距离上次成功检查超过 24 小时，再在后台检查更新，并提供手动刷新入口。

成功下载后先校验结构、唯一 ID 与头像路径，确认有效再替换本地缓存；网络失败或内容无效时继续显示旧名单。头像失败时使用默认头像，不影响其余内容。获取头像时将路径限制在仓库的 `avatars/` 目录内。

应用应只在自己的设置页面处理名单更新，不需要让 SystemUI 持续轮询。仓库建立后仍需在应用中接入上述读取和缓存逻辑，名单才会自动更新。
